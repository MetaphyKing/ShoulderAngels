# ShoulderAngels

> **Two voices debate your coding path forward.**
> A *safe* angel and a *bold* angel each propose a development strategy for the
> same task. You pick one — or ask for both — and the tool forecasts concrete
> outcomes for the path chosen. Every decision is logged so you can revisit the
> forks in the road later.

## Why this exists

Most build decisions are made by momentum. The first plausible idea becomes *the*
plan, and the road not taken is never examined. ShoulderAngels makes the fork
**explicit**: it always produces two genuinely different strategies — one
conservative, one ambitious — labels each with effort/risk/upside, and forecasts
what actually happens if you commit. The point isn't to be told what to do; it's
to make a *deliberate* choice with the tradeoffs on the table.

It is intentionally tiny: one Python module, no runtime dependencies, one LLM
call as the core. That makes it trivial to drop into any repo, CI job, or agent
swarm. Anthropic is the default backend; a Grok Bot (or any host LLM) can
supply `complete` instead — no `ANTHROPIC_API_KEY` required on that path.

## What it does

Given a task ("Add rate limiting to a Flask API"), ShoulderAngels:

1. **Proposes** two competing strategies via the embedded model:
   - 🔰 **safe** — boring, low-risk, guaranteed
   - ⚡ **bold** — ambitious, experimental, higher-risk
   Each is a structured object: `description`, `effort`, `risk`, `upside`.
2. **Chooses** a path — interactively (on a TTY), via `--choose`, or via a
   programmatic `chooser` callback. In pipelines it defaults to `safe` and never
   blocks.
3. **Forecasts** three concrete outcomes for the chosen path (or both).
4. **Records** the decision to an append-only history ledger.

## Install

```bash
# From the repo (editable install gives you the `shoulderangels` command):
git clone https://github.com/MetaphyKing/ShoulderAngels.git
cd ShoulderAngels
pip install -e .

# Or just run the single file — no install required:
python shoulderangels.py "your task" --choose safe --json
```

Anthropic is optional. To run without an API key, use `--backend command`
and a completer script (see [Quick start](#quick-start)).

## Requirements

- **Python 3.10+** (uses `X | None` typing syntax)
- **A completer**, one of:
  - Anthropic: `ANTHROPIC_API_KEY` (default `--backend anthropic`)
  - Agent / Grok host: `--backend command` + `--complete-cmd` (no Anthropic key)
  - Library: any `Completer` (`complete(prompt, system="") -> str`)
- **Runtime dependencies: none** — standard library only
- Dev/test: `pytest` (`pip install -e ".[dev]"`)

## Quick start

**Anthropic (default):**

```bash
export ANTHROPIC_API_KEY=sk-ant-...

# Interactive (asks you to choose):
shoulderangels "Add caching to the user service"

# Pipeline-friendly (no prompt, JSON out):
shoulderangels "Migrate to async" --choose bold --json

# Compare both paths on paper:
shoulderangels "Replace REST with GraphQL" --choose both --json
```

**Agent / Grok host (no Anthropic key):** the host LLM supplies completions;
this tool still validates JSON, chooses, forecasts, and writes history.

```bash
# Offline demo (canned replies — no network):
shoulderangels "Add rate limiting" --choose safe --json \
  --backend command \
  --complete-cmd "python examples/fake_completer.py"

# Same via env (Grok Bot / CI can set these):
export SHOULDERANGELS_BACKEND=command
export SHOULDERANGELS_COMPLETE_CMD='python /path/to/host_completer.py'
shoulderangels "Add rate limiting" --choose safe --json
```

A production completer reads `{"prompt","system"}` on stdin and writes
`{"text": "..."}` (or raw text) on stdout. See
[INTEGRATION_PLAN.md](INTEGRATION_PLAN.md#3b-grok-bot--agent-host).

## How it works

```
                       ┌──────────────────────────────────────────┐
   "Add rate limiting" │  propose()                               │
        ───────────────▶  LLM → {safe:{…}, bold:{…}} (validated)  │
                       └───────────────┬──────────────────────────┘
                                       │ choose: --choose / TTY / callback / "safe"
                                       ▼
                       ┌──────────────────────────────────────────┐
                       │  forecast(chosen) → 3 concrete outcomes   │
                       └───────────────┬──────────────────────────┘
                                       ▼
                       result dict  ──▶  ~/.shoulderangels/history.json
```

The model is called through `Completer.complete(prompt, system)` — implemented
by `LLMClient` (Anthropic), `CallableClient`, `CommandClient`, or any duck-typed
host. Responses are parsed with `extract_json()`, which tolerates raw JSON,
```json fences, and JSON buried in prose. If the model returns nothing usable,
the result is normalized to valid `safe`/`bold` objects with sensible defaults
rather than crashing.

## CLI reference

```
shoulderangels [target] [--choose {safe,bold,both}] [--json] [--model ID]
               [--max-tokens N] [--backend {anthropic,command}]
               [--complete-cmd CMD] [--no-store] [--history] [--version]
```

| Argument / flag     | Meaning                                                            |
|---------------------|-------------------------------------------------------------------|
| `target`            | The task string, **or a path to a file** describing the task.     |
| `--choose`          | Force `safe`, `bold`, or `both`; skips the interactive prompt.     |
| `--json`            | Emit the full result as JSON.                                      |
| `--model ID`        | Anthropic model id (default: `$ANTHROPIC_MODEL` or `claude-haiku-4-5`). |
| `--max-tokens N`    | Token cap per Anthropic call (default 1024).                      |
| `--backend`         | `anthropic` (default) or `command`. Also `$SHOULDERANGELS_BACKEND`. |
| `--complete-cmd CMD`| Completer process for `--backend command` (`$SHOULDERANGELS_COMPLETE_CMD`). |
| `--no-store`        | Do not append this decision to history.                            |
| `--history`         | Print the decision history and exit.                              |
| `--version`         | Print version and exit.                                           |

**Interactive vs. non-interactive:** the prompt appears *only* when stdin is a
TTY and `--choose` was not given. In CI, cron, or pipes it never blocks.

    "effort": "low",                      // low | medium | high | unknown
    "risk": "low",
    "upside": "Battle-tested, minimal code changes"
  },
  "predicted_outcomes": {                 // keyed by path
    "safe": "1. ...\n2. ...\n3. ..."
  },
  "safe_risk": "low",
  "bold_upside": "Highly customizable",

```

## Library API

```python
from shoulderangels import ShoulderAngels, LLMClient, CallableClient

tool = ShoulderAngels()                       # Anthropic; uses ANTHROPIC_API_KEY
result = tool.run("Introduce feature flags", choice="bold")

# Just the strategies, no forecast:
strategies = tool.propose("Adopt event sourcing")

# Custom decision policy instead of a human:
tool.run("Shard the database",
         chooser=lambda s: "bold" if s["bold"]["risk"] != "high" else "safe")

# Custom Anthropic model / budget:
tool = ShoulderAngels(client=LLMClient(model="claude-haiku-4-5", max_tokens=2048))

# Host LLM / Grok Bot — no Anthropic key:
tool = ShoulderAngels(client=CallableClient(lambda prompt, system: host.generate(prompt, system)))
tool.record(result)   # append a finished decision without re-running propose
```

`client` is typed as `Completer`: any object exposing
`complete(prompt, system="") -> str`. `LLMClient` remains importable;
`AnthropicClient` is an alias. See [EXAMPLES.md](EXAMPLES.md) and
[INTEGRATION_PLAN.md](INTEGRATION_PLAN.md#3b-grok-bot--agent-host).

## Decision history

Unless `--no-store` is passed, every run is appended to
`~/.shoulderangels/history.json` as a JSON list. Inspect it:

```bash
shoulderangels --history
shoulderangels --history --json | jq '.[].chosen_path'
```

A corrupt or missing history file is treated as empty rather than fatal.

## Configuration

| Setting          | Where                                   | Default                          |
|------------------|-----------------------------------------|----------------------------------|
| Backend          | `--backend` / `SHOULDERANGELS_BACKEND`  | `anthropic`                      |
| Completer cmd    | `--complete-cmd` / `SHOULDERANGELS_COMPLETE_CMD` | *(required if backend=`command`)* |
| API key          | `ANTHROPIC_API_KEY`                     | required **only** for Anthropic  |
| Model            | `--model` / `ANTHROPIC_MODEL`           | `claude-haiku-4-5`               |
| Max tokens       | `--max-tokens`                          | 1024                             |
| Timeout          | `LLMClient` / `CommandClient(timeout=)` | 60s                              |
| Retries          | `LLMClient(max_retries=...)`            | 3 (on 408/429/5xx & net errors)  |
| History file     | `ShoulderAngels(store=...)`             | `~/.shoulderangels/history.json` |

## Error handling

| Situation                  | Behavior                                                |
|----------------------------|---------------------------------------------------------|
| `ANTHROPIC_API_KEY` unset  | Anthropic backend: exit 1, "export your key" on stderr. Command backend: not required. |
| `--backend command` w/o cmd| exit 2; pass `--complete-cmd` or `SHOULDERANGELS_COMPLETE_CMD` |
| Completer cmd non-zero / empty / timeout | exit 1, `LLMError` on stderr                  |
| Network down / timeout     | Anthropic: retry with backoff, then exit 1              |
| 429 / 5xx                  | retried up to 3× with exponential backoff               |
| Model returns non-JSON     | normalized to valid safe/bold objects with defaults     |
| Piped input, no `--choose` | defaults to `safe`; never hangs                         |
| Bad CLI usage              | exit 2 (argparse)                                       |

## Design principles

- **Stdlib only at runtime.** No `requests`, no SDK — just `urllib`. Copy the
  one file anywhere and it runs.
- **Fail loud, fail clear.** Every failure mode maps to an actionable message.
- **Never block a pipeline.** Interactivity is opt-in and TTY-gated.
- **Validated model output.** The LLM is treated as untrusted input.
- **One shared LLM contract** (`Completer.complete(prompt, system)`) across all
  Organism tools, so they interoperate and share transports. Anthropic is one
  backend; agent hosts are first-class.

## Cost

Each single-path run makes **two** model calls (propose + forecast); `--choose
both` makes **three**. On `claude-haiku-4-5` with the default 1024-token cap this
is fractions of a cent per decision. Lower `--max-tokens` for cheaper calls.

## Troubleshooting

- **"ANTHROPIC_API_KEY is not set"** — either `export ANTHROPIC_API_KEY=sk-ant-...`
  or switch to `--backend command` / a `CallableClient` (no key needed).
- **It hangs waiting for input** — you're on a TTY without `--choose`; either
  answer the prompt or pass `--choose safe|bold|both`.
- **"API HTTP 401"** — bad/expired key. **"HTTP 429"** — rate limited; it
  retries, but slow down or raise your limit.
- **Model id error** — pass a valid `--model` or set `ANTHROPIC_MODEL`.

## FAQ

**Is it deterministic?** No — it's advisory by nature. Pin a model and keep
`history.json` if you need a record of *what was decided*.

**Does it run my code?** No. It only calls the model and writes the history file.

**Can I use a non-Anthropic model?** Yes. Inject any `Completer`
(`complete(prompt, system)`), wrap a function with `CallableClient`, or run
`--backend command --complete-cmd ...`. No Anthropic key on those paths.

**Why two calls?** One to generate the strategies, one to forecast the chosen
path. Use `--max-tokens` to keep them cheap.
